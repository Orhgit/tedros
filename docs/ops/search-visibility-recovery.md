## 5. הצומת הפתוח — ומה תלוי בו

**בדיקה נדרשת: GSC ← אבטחה ופעולות ידניות ← פעולות ידניות.**
אין לכך API. דורש פתיחה ידנית של הממשק. **זו המשימה החוסמת.**

### מסלול א׳ — יש פעולה ידנית

1. לתעד את סוג הפעולה ואת ההיקף (כל האתר / חלקי).
2. לוודא שהניקוי מכסה את מה שצוין — רוב הסיכויים שכבר כן (§3).
3. **להגיש בקשה לבדיקה מחדש** עם פירוט: מה היה, מה הוסר, מתי.
4. המתנה: שבועות עד חודשים. בלי הבקשה — **שום דבר לא יחזור, כמה שנחכה.**

### מסלול ב׳ — אין פעולה ידנית

1. הירידה אלגוריתמית או חיצונית.
2. התנאים להתאוששות כבר קיימים — נשארת סבלנות.
3. אם אין שיפור עד **2026-10-15** (חודש מהאיחוד) → §7.

## 7. מתי לקבוע שזו לא הסיבה

אם עד **2026-10-15** אין שיפור מדיד, ובהנחה שאין פעולה ידנית:

1. לבדוק האם אתרים דומים בנישה נפגעו באותו תאריך (הצלבה חיצונית).
2. לבחון מחדש את היפותזת חור-הדיווח — לגוגל היו באגי GSC מתועדים באוגוסט 2026.
3. לשקול נכס GSC חדש (`sc-domain:`) כדי לשלול בעיה ברמת הנכס.
4. **לקבל את זה כאובדן ולהשקיע בתוכן חדש** במקום להמשיך לרדוף — האתר נקי, מהיר ויציב; זה הבסיס הנכון לצמיחה מחדש בכל מקרה.

## 9. חובות פתוחים שאינם חוסמים

- **טוקן API בטקסט גלוי בקרונטאב של root** — ובשרת הזה נמדדו ~200 סריקות `.env` בלוג אחד. להעביר לקובץ env ולסובב.
- **Cloudflare לא מול האתר** — אין CDN, אין מטמון. ריסטארט = downtime מלא. דורש פעולה מול הרישום.
- **TED-161** — לטנא בריאות ארבעה מספרי טלפון סותרים.
- **TED-156** — audit של ~200 מספרי טלפון ולינקים חיצוניים בתוכן.
