## 4. Execution mechanism — how work actually happens

### The two parallel stacks

```
┌──────────────── MULTICA (planning + tracking) ────────────────┐
│  Issues TED-N   →   PM agent splits   →   Specialist assigned │
│  Master Tracker (TED-10) shows phase status                    │
└────────────────────────────────────────────────────────────────┘
                                ↓
┌──────────────── GITHUB (code + delivery) ──────────────────────┐
│  Specialist creates `agent/<role>/<id>` branch                 │
│  Implements per spec → opens PR → QA agent reviews → human     │
│  approves → merge to main → Multica issue auto-closed          │
└────────────────────────────────────────────────────────────────┘
```

### Today's bottleneck

The chain breaks at **"human approves"**: 15 PRs are open, only 3 have been merged. Every Phase 2/3 deliverable on the agent branches is logically done — it just isn't on `main`.

### Three options to clear the bottleneck

| Option                                                           | Speed  | Risk   | Cost            |
| ---------------------------------------------------------------- | ------ | ------ | --------------- |
| **A. Manual review** by you, PR by PR                            | Slow   | Low    | Time-intensive  |
| **B. `/ultrareview`** (multi-agent cloud review) for each PR     | Medium | Low    | Per-review cost |
| **C. Trust merge** — merge all PRs that pass QA agent + CI green | Fast   | Medium | Tech debt risk  |

**Recommendation**: B for PRs touching schema or auth (#11, #13, #14, ADR PRs); C for content/SEO/docs PRs (#4, #6, #7, #9, #18); A for the 3 biggest feature PRs (#16 calculator, #17 listings, #12 leads).
